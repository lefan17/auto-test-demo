# 测试报告模板

> 自动化跑完只是"跑完"，**能说清楚结果**才是交付。
> 这份模板给的是结构，填的时候删掉不适用的部分即可。

## 一、报告头部

```markdown
# <项目名> 测试报告

| 项 | 内容 |
|---|---|
| 报告版本 | v1.0 |
| 测试轮次 | 第 1 轮（回归轮：第 N 轮） |
| 测试环境 | <环境地址> / <系统版本> / <数据库版本> |
| 被测版本 | <commit hash 或构建号> |
| 测试时间 | 2025-08-01 10:00 ~ 2025-08-01 18:00 |
| 执行人 | <姓名> |
| 用例总数 | 105 |
```

> **"被测版本"这一行最容易被省略，也最要命。**
> 报告不加 commit hash，一周后没人说得清这份报告测的到底是哪一份代码，
> 缺陷复现时全靠猜。

## 二、执行结果

```markdown
## 测试结果

| 模块 | 用例数 | 通过 | 失败 | 跳过 | 通过率 |
|---|---|---|---|---|---|
| 接口测试 | 62 | 62 | 0 | 0 | 100% |
| MES 业务 | 29 | 29 | 0 | 0 | 100% |
| UI 测试 | 14 | 13 | 1 | 0 | 92.9% |
| **合计** | **105** | **104** | **1** | **0** | **99.0%** |
```

> **通过率 100% 的报告要先怀疑，再高兴。**
> 通常意味着三种情况之一：用例太浅（只测了正常流程）、
> 断言太弱（只断言状态码不断言响应体）、或者有失败被"已知问题"跳过了。
> 在报告里写一句"本轮通过率 100%，主要覆盖正常流程与常见异常，
> 未覆盖并发与性能"比光写个 100% 诚实得多。

## 三、缺陷清单

```markdown
## 缺陷清单

| 编号 | 级别 | 标题 | 复现步骤 | 对应用例 | 状态 |
|---|---|---|---|---|---|
| BUG-001 | 中 | 任意用户名+正确密码即可登录 | 1. POST /api/login 2. username=nobody 3. password=123456 | LC-02 | 待确认 |
| BUG-002 | 中 | token 为固定值且无过期 | 连续两次登录，token 均为 demo-token-123 | LC-27 | 待确认 |
```

**级别怎么定**（比"严重/一般"更好用的判据）：

| 级别 | 判据 |
|---|---|
| 高 | 数据丢失/错乱、资金相关错误、核心流程不可用、安全问题 |
| 中 | 功能不符合需求、明显影响体验、有安全隐患但需特定条件触发 |
| 低 | 文案/样式、边界处理不优雅、不影响主流程的小偏差 |

> 定级的关键不是"我觉得严重不严重"，而是**说清楚影响范围和触发条件**。
> "任意用户名都能登录"听起来比"密码框没 trim"严重，就是因为
> 前者的影响范围是**所有人**，后者只在**用户手滑多敲空格**时出现。

## 四、测试结论

```markdown
## 结论

**建议：有条件通过 / 不通过 / 通过**

本轮共执行 105 条用例，通过 104 条，失败 1 条，发现 2 个待确认缺陷。

- 1 条失败用例为 UI 用例，原因为测试环境网络出口不可用
  （`net::ERR_CONNECTION_CLOSED`），**非产品缺陷**，待网络恢复后重跑。
- BUG-001（无用户校验）为已知设计简化，当前仅用于演示环境，
  上生产前必须修复。

**未覆盖范围**：性能/压力、并发一致性、安全渗透、兼容性测试。
```

> 结论部分必须回答三个问题：
> **能不能上（建议）、为什么（依据）、还有什么没测（边界）**。
> 只写"测试通过"的报告等于没写结论 —— 因为读报告的人
> 需要的是决策依据，不是一句口号。

## 五、附：一份好报告与一份坏报告

| | 坏报告 | 好报告 |
|---|---|---|
| 结果 | "测完了，基本没问题" | 105 条 / 通过 104 / 失败 1（原因：环境网络，非缺陷） |
| 缺陷 | "有些小问题" | BUG-001 影响所有用户，BUG-004 仅影响手滑多敲空格的用户 |
| 结论 | 无 | 建议有条件通过，上生产前须修 BUG-001 |
| 边界 | 不提 | 明确列出未覆盖并发与性能 |
| 可复现 | 无版本信息 | 标注 commit hash 与用例编号 |

**核心区别**：好报告的每一句话都能被**追问**并答上来。
"基本没问题"没法追问（追问就是"到底有没有问题"），
"104/105 通过，1 条因环境失败"可以追问到具体是哪条、为什么。
