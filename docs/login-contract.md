# 登录服务契约

> 被测服务的接口约定。实现见 `login_app/app.py`，用例见 `testcases/login/`。
> 契约由 `testcases/login/contract.py` 以可执行的形式保存一份，两边要同步改。

## 为什么单独维护一份契约

契约的价值在于**它是"应该是什么样"，而不是"现在是什么样"**。
一旦从实现里反向生成契约，契约测试就退化成"实现测试"——
实现返回什么就断言什么，失去了发现偏差的能力。

本项目的 `login_app` 是**故意带缺陷**的（见 `login_app/app.py` 的 6 个发现点），
所以"契约"和"实现"在这里**天然不一致**，正好用来演示这件事：

| 契约里定义的 | 实现实际的行为 | 差异 |
|---|---|---|
| 只接受 `application/json` | 还额外接受表单提交 | FIND-02（实现比契约宽松） |
| 缺字段返回 400 | 密码传数字 0 也返回 400 | 一致（0 被当成 falsy） |
| 401 表示"用户名或密码错误" | 只要密码对，用户名随便 | FIND-01（实现比契约宽松） |
| 未定义 token 的生命周期 | token 是固定值、不过期 | FIND-06（实现缺失，契约也没写） |

最后一行是个典型例子：**契约没写的东西，实现就可以随便来。**
"token 有效期"没进契约，于是实现给了一个永久固定的 token 也没人拦。
这就是为什么契约评审值得单独花时间。

## 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查，返回 `{"status","version"}` |
| POST | `/api/login` | 登录，见下 |
| GET | `/api/flaky` | 约 10% 概率返回 503，用于验证重试策略 |

## POST /api/login

**请求**（`Content-Type: application/json`）

```json
{"username": "admin", "password": "123456"}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名。实现会 trim 前后空格 |
| `password` | string | 是 | 密码。**实现不做 trim**（与 username 不对称，见 FIND-03） |

**响应**

| 状态码 | 语义 | 响应体 |
|---|---|---|
| 200 | 登录成功 | `{"token": "...", "user": "..."}` |
| 400 | 缺少用户名或密码 / 请求体不是合法 JSON | `{"error": "..."}` |
| 401 | 密码错误 | `{"error": "invalid credentials"}` |

**契约未定义、但实现会返回的状态码**

| 状态码 | 何时出现 | 说明 |
|---|---|---|
| 405 | 用 GET 等非 POST 方法访问 | 框架层行为，契约漏写，见用例 LC-28 |
| 422 | 理论上 pydantic 校验失败时 | 当前实现手工解析请求体以避免 422，见 LC-29 的说明 |

## 关于 400 与 422

这一条值得单独说，因为它是**框架默认行为与业务契约打架**的典型现场。

FastAPI / Starlette 的默认行为是：请求体解析失败 → **422**。
而本接口的契约要求 **400**（"参数格式错误"是客户端问题，不是语义问题）。
两者的区别：

- **400 Bad Request** —— 请求本身有问题（格式、语法）。客户端改请求就能解决。
- **422 Unprocessable Entity** —— 请求格式没问题，但语义不对（字段类型对、业务规则不满足）。

原实现（Flask）返回 400。用 FastAPI 重写时，如果图省事直接用 pydantic 模型接参数，
缺字段就会变成 422，**契约被框架默认值悄悄改掉了**。

所以 `login_app/app.py` 里**手工读请求体**而不是用 pydantic 模型接参 ——
代码看起来"不够 FastAPI"，但保住了契约。用例 LC-29 把这条钉住了。

> 这是"用框架"和"被框架用"的分界线：
> 框架的默认值大多数时候是对的，但当它和你的契约冲突时，
> **你得知道默认值是什么，并且有意识地覆盖它**，而不是事后发现线上返回的
> 状态码和接口文档对不上。
