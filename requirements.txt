# 重跑治理（flaky 用例与隔离区，见 docs/wave2-flaky-handoff.md）。
# 只 pin 这一个直接依赖：它的元数据只声明 pytest!=8.2.2,>=8.2 与 packaging>=17.1
# 两个下界（Requires-Python >=3.10），两者本文件与 lock 里都已有更严的 pin，
# 不需要在这里再抄一遍——传递依赖由 requirements.lock 全量钉死。
# 为什么**不能**顺手在 pytest.ini 的 addopts 里写全局 --reruns：
# 全局重跑会对**每一条**用例生效，真回归（断言写错、接口字段被改坏）只要第二次
# 侥幸通过就会被吞成绿灯，门禁只剩一个装饰性的绿色。所以只有显式标了
# flaky marker 的用例才重跑，并且用 only_rerun 把重跑收窄到「第三方抖动」指纹
# （429/5xx、连接失败、响应过慢）；不匹配指纹的失败当场硬失败，一次都不重跑。

# === Mock 后端（testcases/mes/ 的业务全链路用例需要，见 mock_server/） ===
# 放在同一个文件里，是为了让"一条 pip install 就能跑全部用例"成立。
# 拆成两个依赖文件时，只装根依赖的人跑 pytest -m mes 会直接
# 报 ImportError: No module named 'fastapi'——分成两个文件省下的那点安装时间，
# 远抵不过"新同事照 README 做完却跑不起来"的代价。

# === 契约驱动测试（testcases/contract/，见 docs/wave1-contract-handoff.md） ===
# schemathesis 从 docs/openapi.json 生成请求做属性测试，所以它和 pytest / jsonschema
# 必须装在同一个环境里——只装 pytest 的人跑 pytest -m contract 会 ImportError，
# 和上面 Mock 后端段是同一个理由。
# 只 pin 直接依赖 schemathesis：它自己声明的依赖（hypothesis、httpx、werkzeug、
# yarl、click、jsonschema-rs 等）交给 pip 解析。这里不照抄一份传递依赖清单，是因为
# 传递依赖一旦由本文件接管，就会和 schemathesis 自身的版本约束打架，
# 而 requirements.lock（pip-compile 产物）本来就会把解析结果全量钉死。
# 实测（python 3.12.10）解析结果：hypothesis==6.169.1、hypothesis-graphql==0.13.2、
# jsonschema-rs==0.58.6、pyrate-limiter==4.5.0、rich==15.0.0、anyio==4.15.1、
# werkzeug==3.1.9、harfile==0.5.0。4.x 起 schemathesis 不再声明 starlette，
# 所以 starlette 只由 fastapi 段约束（详见本文件上方 fastapi 的注释）。
# 4.x 起 OpenAPI 3.1 是原生支持，`schemathesis.experimental` 整个模块已被删除
# （4.31.1 wheel 里没有该目录），契约测试里原先那句 import 期的
# `schemathesis.experimental.OPEN_API_3_1.enable()` 已随之删掉。
schemathesis==4.31.1
